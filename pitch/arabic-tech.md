# 🚌 آمن مدرستي - تقرير البنية التقنية (Technical Architecture Report)

## 1. الملخص التنفيذي
منصة **"آمن مدرستي"** هي نظام سحابي متعدد المستأجرين (Multi-tenant) يعتمد على إنترنت الأشياء (IoT) لضمان سلامة النقل المدرسي. يوفر النظام تتبعاً مباشراً للموقع عبر GPS، وبثاً مرئياً مباشراً، وتسجيلاً آلياً لحضور الطلاب باستخدام تقنيات RFID. يربط النظام بين السائقين، وأولياء الأمور، وإدارات المدارس من خلال واجهة ويب موحدة، مما يضمن الشفافية والامتثال لمعايير السلامة.

---

## 2. الهيكلية عالية المستوى (High-Level Architecture)

يتبع النظام معمارية **جاهزة للخدمات المصغرة (Microservices-ready)** باستخدام حاويات Docker، ومنسقة لمعالجة تدفق البيانات في الوقت الفعلي من الأجهزة المحمولة ومستشعرات إنترنت الأشياء.

### 🏗️ المكدس التقني (The Stack)
| المكون (Component) | التقنية (Technology) | الدور (Role) |
| :--- | :--- | :--- |
| **النواة الخلفية (Backend)** | **Python Flask** | معالجة واجهات برمجة التطبيقات (REST API) والمنطق البرمجي. |
| **محرك الوقت الفعلي** | **Socket.IO / Eventlet** | اتصال ثنائي الاتجاه (بين الهاتف والسيرفر) للتحديث اللحظي. |
| **بروتوكول IoT** | **MQTT (Mosquitto/HiveMQ)** | رسائل خفيفة الوزن لنقل بيانات GPS والأجهزة. |
| **قواعد البيانات** | **PostgreSQL + PostGIS** | بيانات علائقية + استعلامات جغرافية مكانية (للخرائط). |
| **الواجهة الأمامية** | **HTML5 PWA + Leaflet.js** | تطبيقات ويب تعمل كبرامج أصلية (لا تتطلب متجر تطبيقات). |
| **البث المرئي** | **HLS / WebRTC** | نقل الفيديو بزمن وصول منخفض (Low-latency). |
| **النشر والتشغيل** | **Docker Compose** | بيئة حاويات لضمان سهولة النقل والتشغيل الفوري. |

## 3. تنفيذ العتاد والأجهزة (الحافلة الذكية)

نعتمد نهج **"وحدة التحكم الشاملة" (All-in-One Android Console)** لتقليل التوصيلات المعقدة ومخاطر البطاريات، مع دمج ملحقات USB تعمل بمجرد التوصيل (Plug-and-Play).

### أ. مركز القيادة (وحدة السائق)
* **الجهاز:** وحدة تحكم أندرويد للوحة القيادة (مثل **Phisung K18**) أو شاشة سيارة ذكية.
* **نظام التشغيل:** Android 8.1 / 10.
* **الاتصال:** منفذ شريحة **4G LTE مدمج** + Wi-Fi.
* **الوظيفة:** تشغيل *تطبيق السائق*، العمل كبوابة GPS، وعرض المسار.

### ب. حضور الطلاب (بدون تلامس / Hands-Free)
* **الجهاز:** قارئ UHF RFID مكتبي (USB).
* **الوضع:** محاكاة لوحة المفاتيح (HID Keyboard Emulation).
* **التكامل:** يُوصل مباشرة بمنفذ USB في شاشة الأندرويد.
* **آلية العمل:**
    1.  يصعد الطالب للحافلة ومعه بطاقة/ملصق UHF في حقيبته.
    2.  يلتقط القارئ البطاقة (المدى: ~1 متر).
    3.  يقوم القارئ "بكتالة" الرقم التعريفي تلقائياً في الحقل المخفي بتطبيق السائق.
    4.  يرسل التطبيق حالة `BOARDED` (تم الصعود) للسيرفر فوراً.

### ج. المراقبة (الفيديو)
* **الكاميرا الأساسية:** كاميرات مدمجة مزدوجة في وحدة الأندرويد (أمامية للطريق + داخلية للركاب).
* **البروتوكول:** التطبيق يبث عبر Android Camera API -> WebRTC/RTMP -> السيرفر.

## 4. تدفق البيانات والاتصالات (Data Flow)

### 📡 1. حلقة تتبع الموقع (GPS Tracking Loop)
1.  **المصدر:** تطبيق السائق يقرأ `navigator.geolocation` من وحدة الأندرويد.
2.  **النقل:** إرسال `{lat, lng, speed, bus_id}` عبر **Socket.IO** كل 3 ثوانٍ.
3.  **السيرفر:** يستقبل Python Flask البيانات ويحدث جدول `buses` في قاعدة البيانات (PostGIS).
4.  **البث:** يقوم السيرفر بفلترة أولياء الأمور النشطين ويبث حدث `update_map`.
5.  **الوجهة:** يستقبل تطبيق ولي الأمر الإحداثيات ويحرك أيقونة الحافلة على الخريطة.

### 📝 2. حلقة الحضور (Attendance Loop)
1.  **المصدر:** قارئ UHF يدخل رقم البطاقة في تطبيق السائق.
2.  **المنطق:** التطبيق يتحقق من الحالة السابقة (هل هو صعود أم نزول؟).
3.  **النقل:** إرسال حدث `student_scan` عبر Socket.IO.
4.  **السيرفر:**
    * يسجل الوقت في `trip_logs`.
    * يحدث `bus_manifest` (قائمة الركاب الحاليين).
    * يرسل **إشعار (Push Notification)** لولي الأمر المحدد ("أحمد صعد إلى الحافلة 101").

## 5. الوحدات البرمجية (واجهات المستخدم)

### 👨‍💼 لوحة المسؤول العام ومدير المدرسة
* **التقنية:** لوحة تحكم ويب (Jinja2 Templates).
* **الميزات:**
    * **إدارة الأسطول:** إضافة/حذف الحافلات وتعيين السائقين.
    * **إدارة RFID:** ربط أرقام البطاقات بملفات الطلاب.
    * **الخريطة الحية:** "نظرة شاملة" (God View) لجميع الحافلات في وقت واحد.

### 🚌 تطبيق السائق (Driver App)
* **المنصة:** تطبيق ويب (PWA) يعمل على متصفح الأندرويد.
* **الميزات:**
    * **واجهة بأزرار كبيرة:** "بدء الرحلة" / "إنهاء الرحلة".
    * **القائمة الحية:** تعرض قائمة الطلاب المتواجدين حالياً على متن الحافلة.
    * **التدخل اليدوي:** إمكانية تحضير الطالب يدوياً في حال نسيان البطاقة.

### 👨‍👩‍👧‍👦 تطبيق ولي الأمر (Parent App)
* **المنصة:** متصفح الجوال (Mobile Browser).
* **الميزات:**
    * **أطفالي فقط:** فلتر أمان يعرض فقط أبناء المستخدم المسجل للدخول.
    * **التتبع المباشر:** رؤية موقع الحافلة *فقط* عندما يكون الطفل على متنها.
    * **مؤشرات الحالة:** "في المدرسة"، "في الحافلة"، "في المنزل".

## 6. الأمان وقابلية التوسع (Security & Scalability)

1.  **الاحتواء (Dockerization):**
    * يعمل النظام بالكامل (قاعدة البيانات، التطبيق، الوسيط) في حاويات معزولة.
    * *الفائدة:* قابل للنشر على أي خادم سحابي أو محلي بضغطة زر واحدة.
2.  **متغيرات البيئة (Environment Variables):**
    * كلمات المرور ومفاتيح API لا يتم تضمينها في الكود مطلقاً؛ بل يتم حقنها وقت التشغيل.
3.  **التشفير (SSL/TLS):**
    * جميع اتصالات الويب مؤمنة عبر HTTPS (مطلب أساسي لتصريح الكاميرا والموقع).
    * اتصالات MQTT مشفرة (Port 8883) لضمان أمان الأجهزة.

## 7. خارطة الطريق المستقبلية (Future Roadmap)

* **كشف الإرهاق بالذكاء الاصطناعي:** استخدام الكاميرا الأمامية لوحدة الأندرويد لتحليل وجه السائق وتنبيهه عند النعاس.
* **تحسين المسارات:** دمج Google Maps API لاقتراح مسارات أسرع بناءً على حركة المرور.
* **الوضع غير المتصل (Offline Mode):** تخزين بيانات GPS محلياً في حال انقطاع 4G ومزامنتها عند عودة الاتصال.
